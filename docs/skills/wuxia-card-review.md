# Skill: 卡牌评审与改卡候选

## 适用场景

用户询问某张卡是否太强/太弱、是否符合人物形象、某个修改是否合理，或要求生成新版卡牌文本。

## 评审维度

- 艺术形象符合度。
- 规则稳定性。
- 文本清晰度。
- 是否可能产生无限循环或难以解释的裁定。
- 实际玩法强度。
- 卡面强度与抓牌出战价值的区别。
- 与已有角色生态的关系。
- 电子化风险。

## 强度校准

用户给过强度参考：

- 极强或顶层常见例：葵花老祖、东方不败、张三丰、独孤求败、萧秋水（大侠）、传鹰、张小凡、浪翻云、韦青青青、金世遗、杨小邪、黄裳、成吉思汗。
- 很强但不一定顶层例：燕狂徒、赤尊信、元十三限、方歌吟、关七、诸葛正我、萧峰、郭靖、杨过（大侠）、黄蓉、张无忌、阿青。
- 特异化长板不等于综合强，例如白飞飞、和尚大师、雪峰神尼等。
- 不占名额会显著影响实战价值，例如方恨少卡面弱但出战价值不能简单按弱卡算。

这些是作者体感校准，不是绝对数学排序。

## 改卡流程

1. 查询当前文本、卡面和已有裁定。
2. 说明现状和风险。
3. 给出候选新版文本。
4. 说明改动点。
5. 等作者确认。
6. 确认后才更新源数据、Excel、PSD 和更新日志。

## 写入位置

- 未确认候选：`data/change_candidates.json`
- 强度、定位、风险、攻略、AI 评语：`data/card_reviews.json`
- 确认后的牌面事实：源数据层。

## 禁止事项

- 不要把 AI 评语直接写成卡牌事实。
- 不要因为自己觉得合理就修改源数据库。
- 不要假装已经理解所有复杂特技。
