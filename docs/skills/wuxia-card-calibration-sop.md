# 五行卡牌模块化评审规范

## 一、单卡原子流程

每次只分析一张卡：

1. 读取最小核心规则。
2. 确认卡牌类别及进入本局方式。
3. 读取对应类别模块。
4. 战斗人物判断主要、次要和保底功能，再读取相关功能模块。
5. 将每条能力挂接到默认游戏流程节点。
6. 只读取实际触发的专项规则、术语和少量同功能案例。
7. 完成逐技事实、组合冲突和物理结算链。
8. 完成类别专属评价、反证和风险。
9. 作者校准后再决定是否锁定。

当前卡未锁定时，不以批量生产方式继续制造后续正式评审。

## 二、类别路由

### 战斗人物

唯一竞争两张战斗人物名额的类别。必须分析：

- 主要、次要和保底功能
- 人物名额价值
- 输出与爆发
- 正面生存
- 侧面生存
- 实际涉及的辅助、控制、调度或全局价值
- 与另一张战斗人物的互补

### 附加人物、物品和称号

摸到后直接进入本局，不需要弃牌，不占两张战斗人物名额。

在“已经进入本局”的前提下，分析其实际帮助、触发率、无效情形和组合上下限。不得虚构携带槽位、取得成本、转移、覆盖或失去规则。

### 场景

场景定义整局环境。评价整局流程变化、策略、规则稳定性和体验，不做普通强度评分。

## 三、战斗人物功能

只有战斗人物按功能路由。主要功能是玩家愿意让其占据一个人物名额的主要理由，不是文字最长的能力。

当前模块：

- 正面作战
- 侧面生存
- 辅助与调度
- 控制与规则干预
- 全局局势与关系政治

跨功能比较时，只能比较具体维度，不能用正面输出差距直接推出整卡强弱。

## 四、基础战斗门槛

战斗人物必须先按基础模型计算：

- 两个内功位、两个招式位。
- 内功克敌100、相平无伤。
- 招式克敌300、相平双方各200。
- 单位置克敌、被克、相平概率分别为`1/5、1/5、3/5`。
- 白人期望输出400。
- 主动大招默认要求放法中每张卡均未被克且至少一张克敌。

简单独立概率优先使用乘法。例如两张均未被克为`(4/5)²=16/25`。

任何主动大招必须写明位置、合法放法、放出率、失败下限和与其他主动能力的位置竞争。未完成时不得把牌面数字计入常态输出。

## 五、工作卡完整性

使用`docs/skills/wuxia-card-review-workcard.md`。

必须独立存在：

- 输出与爆发
- 正面生存
- 侧面生存
- 优点
- 缺点
- 规则风险
- 电子化风险

不适用时写明类别原因，不得静默删除。

## 六、比较案例

只加载同类别、同主要功能、同关键机制的少量案例。比较：

- 常态
- 下限
- 现实上限
- 最早结算时点
- 目标和穿透
- 使用频率
- 失败条件
- 正面和侧面生存
- 人物名额价值或本局边际帮助

具体人物的完整计算进入案例库，不进入核心规则或术语层。

## 七、作者反馈归档

- 普遍流程：核心规则。
- 某项机制的普遍边界：专项规则。
- 特殊词语定义：术语层。
- 类别或功能评法：评价模块。
- 单卡计算：案例和单卡理解。
- 玩家意愿：玩家动态。

禁止把所有反馈都写入`rule_terms.json`。

## 八、反证与问题

反证至少检查：

- 理论对象是否被误当成稳定触发。
- 玩家心理是否被误当成牌面能力。
- 放法、位置、时序、次数或生存是否降低兑现率。
- 多项能力能否在同一合法牌形中成立。
- 大数字、技能数量和文本长度是否造成高估。

待校准问题必须能改变核心玩法、合法结算、强度档、响应窗口、胜负或电子化结构；否则不进入正式问题清单。

## 九、锁定与批次

- 自动工具只能提取事实、检索、校验格式和检查编码。
- 正文、评分、优缺点、玩法、问题和`locked`不得批量自动生成。
- 批次文件只汇编已经逐张锁定的完整评审。
- 新规范不自动追溯重写旧批次；旧评审作为历史材料，必须重新审计后才能成为当前锚点。
