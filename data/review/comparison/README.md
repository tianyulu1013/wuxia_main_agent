# 战斗人物极简横向统计

这里是后续横向比较的默认入口。每个维度只读一个文件，不再默认读取完整`combat_baselines.json`。

- `front-output.json`：正面输出期望、实战穿透输出、实战穿透率，并保留严格一定造成输出。
- `front-hit-count.json`：正面平均击中次数；仅在受击触发、击中追加或按攻击段数防御时读取。前23张均有当前主值；丁喜按约两回合有效使用窗口取首轮近似3次，不继续追求截断联合枚举。
- `non-damage-elimination.json`：杀死、彻底死亡、清除、离场等非伤害淘汰；记录类型、单次条件成功率、预计尝试窗口及生存边界，不折算成输出或穿透。
- `side-output.json`：侧面／场下条件输出、实战穿透输出、实战穿透率，并保留严格一定造成输出。
- `front-survival.json`：正面生存强弱与一句依据。
- `side-survival.json`：侧面生存强弱与一句依据。
- `global-influence.json`：全局影响强弱、主要类型与一句依据。
- `placement-security.json`：名次保障／败局规避强弱与一句依据；不与全局影响或个人生存重复。
- `lifecycle-value.json`：第一轮整局价值速览，登记常态兑现、有效行动／资源链、淘汰成本、净交换和长期结局转化；不是分数。
- `base-life-distribution.md`：全体实体战斗人物卡的不计防御基础生命分布、多人一卡合计口径与例外。
- `mechanism-frequency.md`：异常及解、出血、破、一定造成、转、连绵、清除、杀死的全库牌面出现频率；用于防御环境回归，不等同于实战触发率。
- `ability-type-frequency.md`：423张战斗人物的特技类型、大招数量分布及统一简化放出模型；仅在人物能力依赖大招数量、使用、打断、禁用或复制时按需读取，不是每张人物的默认输入。
- `overall-strength-supervision.md`：作者对当前22张人物给出的监督性综合梯队与顺序，用于发现AI权重倒挂；不是正式评分或绝对裁定。

单卡完整推导仍在`data/review/cards/<卡名>/`。复杂分支、方差、离散分布和公式不复制到这里。

每完成一人，仍须把完整结构化模型写入`data/review/calibrated_stats.json`和`data/review/combat_baselines.json`；这里只承担日常横向速读和全体均值。

每增加一人，输出横表的摘要必须重新计算人物主值的均值、总体标准差、平均实战穿透输出、实战穿透输出总体标准差和合并实战穿透率；严格一定造成输出另行保留。穿透来源高度集中时，还要登记最大来源人物及其占比，避免把少数极端人物造成的均值误认为普遍水平。

## 三轮评测

1. 第一轮：理解机制并建立正面、侧面输出模型；基础平克需要校验时引用白人400，真实人物环境暂取当前抽样均值，登记输出期望、实战穿透输出、实战穿透率、严格一定造成输出和必要的击中次数；杀死、彻底死亡、清除和离场另建非伤害淘汰统计；同时保存常态兑现率、有效行动次数、生命周期价值、淘汰成本、净交换和长期结局转化。
2. 第二轮：全人物第一轮完成后，用全体平均输出、平均实战穿透输出和防御机制回归正面／侧面生存；同时把全局影响拆为辅助队友、削弱敌方、场面控制和谈判能力，并单独回归名次保障／败局规避。
3. 第三轮：基于前两轮的全体分布与分位，统一给各维度打分，再形成总评分与泛用性评分。

白人400只是无能力人物的物理校验，不要求每张卡重复计算。当前23张已评实体卡的正面数值输出均值为1314.42、总体标准差777.82，日常仍暂取约1400作为承伤、生存、受击触发和爆发风险的环境说明；该值随新增样本更新，也不能代替段数、类型、击中次数、穿透分布和非伤害淘汰。

生存横表的基础档位固定为`很弱 < 弱 < 较弱 < 一般 < 较强 < 强 < 很强`。`tier`只负责可排序的基础强弱，形态、阵容、对象和协作条件写入`condition`或`note`。旧人物仍存在的复合语气档位留待第二轮逐人回归，不再作为新条目的写法。

## 综合强度监督

当前22张人物第一次监督性粗排已经暴露出明显的正面战斗权重偏高：AI严重低估丁典，严重高估丁喜，并低估梅念笙、白清儿，过度抬高燕十三。后续形成总评分前，必须先读取`overall-strength-supervision.md`检查相近人物是否出现同类倒挂；不得从输出期望直接推导总强度。
