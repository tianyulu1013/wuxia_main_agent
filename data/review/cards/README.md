# 单卡评价目录

本目录是已重新精评卡牌的默认AI读取入口。每张卡建立独立目录，避免把规则语义、计算、FAQ、风险和横向比较全部塞进一个超长文件。

## 默认读取顺序

1. 先读`<卡名>/README.md`，取得总评、状态和维度路由。
2. 只按当前问题读取一个或数个维度文件。
3. 需要逐字核对作者裁定时才读`author-calibration.md`。
4. 需要追查迁移前上下文时，才读旧`data/review/workcards/`完整归档。

禁止为了评价下一张卡而批量读取本目录全部人物。

## 证据深度要求

分文件只解决“按需读取”，不得用来压缩或删除推理证据：

- `README.md`可以只保存结论和路由。
- `front-output.md`必须保存变量定义、概率来源、逐步公式、联合分布或递推过程、方差计算、死亡／防御截断及数字如何支持强度判断。
- `front-survival.md`和`side-survival.md`必须说明承伤事件模型、环境参数、不能计算固定回合时的原因，不得只报生命和一句结论。
- `gameplay-and-comparison.md`必须保存从机制证据到优缺点、反制、横向锚点和最终强度结论的推理链。
- 结构化JSON中的数字是索引，不替代Markdown中的完整推导。

详细维度文件应做到：后续AI只读取该文件，也能独立复算结论并判断适用边界。

## 每个人物目录

| 文件 | 职责 |
|---|---|
| `README.md` | 简洁总评、状态、维度摘要和文件路由 |
| `mechanics.md` | 牌面事实、发动性质、语义边界、结算链 |
| `front-output.md` | 正面对阵者输出、方差、穿透、失败与上限 |
| `side-output.md` | 侧面目标输出、场下输出、多目标公式与资源共用 |
| `front-survival.md` | 正面承伤、回复、免死和存活模型 |
| `side-survival.md` | 场下防指定、防波及、防伤害和存在状态 |
| `global-influence.md` | 己方辅助、敌方削弱、局势控制、覆盖、持续及双刃风险 |
| `placement-security.md` | 直接胜负、结盟、投靠、免失败与名次保障；不把战斗强度重复计入 |
| `lifecycle-and-realization.md` | 常态兑现率、有效行动次数、生命周期价值、淘汰成本、净交换与长期结局转化 |
| `non-damage-elimination.md` | 仅机制涉及时建立；杀死、死亡、彻底死亡、清除、离场等独立淘汰模型 |
| `gameplay-and-comparison.md` | 实际玩法、优缺点、同功能比较与结论 |
| `risks.md` | 规则风险、电子化风险和文本风险 |
| `wording-ambiguities.md` | 已识别歧义、作者裁定状态与以后可选的消歧建议 |
| `author-calibration.md` | 原问原答FAQ及作者完整回复 |

## 维度边界

- 侧面输出不等于侧面生存。
- 侧面目标输出、人物场下输出、多目标输出分别登记。
- 全局影响力不等于侧面输出，也不等于能力对自己当前战斗的帮助。
- 全局影响力的“影响强度”与“净收益稳定性”分开评价。双刃能力可以影响很强，但净收益不稳定。
- 正面、侧面和全局贡献共享资源时不得重复相加。
- 单回合输出、生存和全局影响必须再通过`lifecycle-and-realization.md`解释怎样兑现为整局净优势；理论上限不能直接替代生命周期价值。
